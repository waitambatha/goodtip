{% comment %} SEARCH RUNS ON THE SERVER, and the list arrives sixty at a time. The client's own worst case is the reason: "an organisation that has about 1000 people". Rendering a thousand rows into every page load is the difference between a panel that opens instantly and one that does not. A real GET form with htmx over the top, so it degrades to an ordinary search that reloads the page. {% endcomment %}
{% comment %} The htmx attributes are on the INPUT, not on the form. An input that carries its own hx-get sends its own name and value, which is exactly the one parameter this needs — no reasoning about which element htmx considers the trigger, and no dependence on how a particular version handles a form's submitter. `delay:280ms` debounces: without it every keystroke is a request, and a name typed at speed fires eight searches whose answers can arrive in any order. The form around it is the no-JavaScript path and posts to the same place. {% endcomment %}
