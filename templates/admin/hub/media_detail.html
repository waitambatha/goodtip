{% extends "admin/hub/base.html" %} {% load i18n %} {% comment %} ONE PICTURE, AND THE ANSWER TO "WHERE IS THIS BEING SHOWN?" That question is the whole reason this feature exists — the client asked for it after somebody wanted a photograph taken off the site and there was no way to find out what taking it off would affect. The answer has two shapes because there are two kinds of picture here, and pretending otherwise would send half the people who read it to the wrong screen: UPLOADED it belongs to a row, and that row's own form is where it is changed. One link, straight there. SHIPS WITH it is named by templates, stylesheets and occasionally a list in THE SITE Python. Every one of those is listed with its line number, and the way to change what a VISITOR sees is the Pages editor, which swaps a photograph without anybody going near the repository. There is deliberately no upload box on the site-picture side. A web request that overwrote a file inside the git checkout would be undone by the next deploy — and because deploy.sh rebases, an uncommitted modified file is a deploy that STOPS, not a change that quietly reverts. Saying so is more use than a button that appears to work. {% endcomment %} {% block hub_accent %}var(--gt-c4){% endblock %} {% block hub_ic %}ic-image{% endblock %} {% block crumbs %}

    {% comment %} REPLACING THE FILE ITSELF. Client, 20 Sep 2026: "yes, add the button with the caveat." The caveat is not a formality and it is not about permissions. `static/` is inside the git checkout and deploy.sh pulls with `git pull --rebase`, so a tracked file modified on the server is not quietly reverted by the next deploy — the rebase REFUSES, and deploys stop until somebody logs in and sorts it out. That is a specific, checkable consequence, so it is stated as one rather than softened into "may affect deployment". The tick box is the whole guard, and it is enough: this is a screen only an administrator with pages.images can reach, and the failure mode is an afternoon of confusion rather than lost data — the old file is one `git checkout` away for as long as nobody commits over it. {% endcomment %}
