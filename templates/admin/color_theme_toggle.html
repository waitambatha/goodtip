{% load i18n %} {% comment %} The theme control, as a segmented switch. It has been through two shapes before this one. Django ships a bare 16px icon that cycles auto -> light -> dark on click, and the client never spotted it. A labelled pill fixed the spotting but kept the cycling, which has the deeper problem: a control that changes meaning every time you press it cannot be aimed. You want dark, you press once, you get light, you press again. Three segments answer both. Every option is visible, the one you are on is filled, and any of them is one click away. There is no hidden state to discover by pressing. Django's theme.js is not used here. It binds to `.theme-toggle` and only knows how to cycle; these buttons each set one mode outright, which is a different behaviour, so the (small) handler lives with the markup. The storage key and the `data-theme` attribute are exactly what Django uses, so its own early-boot script still restores the right theme before first paint and nothing else in the admin has to know this was replaced. {% endcomment %}
